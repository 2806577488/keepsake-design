# 大脑分层查看页（v3.12 · 随 0.4.36 上线）

> 工程侧：`keepsake-app` 的 `lib/features/settings/brain_layers_screen.dart`。
> 语义来源：`dsh-brain` README 的四层（规范 / 角色 / 实体 / 工作记忆）。

## 0. 概念对应

| 层 | App 里的东西 | 谁能改 |
|---|---|---|
| 规范 | 设置 →「专业规范」（用户写的领域规矩）→ `【专业规范】` 注入 | **用户** |
| 角色 | 角色卡人设（用户写）+ 模型写出的「我是谁」（`characters.definition`） | 人设用户改；定义**只读** |
| 实体 | 患者/客户/项目档案（`entities` + 要点 + 关联原文） | **只读**（后台自动维护） |
| 工作记忆 | 每轮注入的 `【当前对象】`+ 记忆/情绪/人格 | 不直接可见 |

## 1. 入口

设置 →「对话默认」→ **大脑分层**（放在「专业规范」下面）。

## 2. 页面结构（自上而下）

| 区块 | 内容 | 空态文案 |
|---|---|---|
| 卡选择 | 角色卡 chips，**只有一张卡时不显示** | — |
| 角色 · 我是谁 | `v{n} 的定义` + 来源（模型写的 / 规则兜底）+ 正文；点击开版本历史 | 「还没写过 · 再聊几轮（或第一次后台整理后）会自动写第一版」 |
| 实体 · 说到谁 | 每行：名字 + 类型（患者/客户/项目/宠物）；点击开详情（要点 + 最近聊到） | 「还没有对象档案 · 对话里出现「患者某某」「客户某某」这类明确称呼时会自动建」 |
| 规范 · 我是怎么答的 | 「专业规范」一行 + 两行预览；点击**返回设置页**去编辑 | 「还没写（设置 → 对话默认里可编辑）」 |

## 3. 两条硬规则

1. **模型写的定义只读**。手改了就分不清"长成的"和"被编辑过的"；要换人设去改角色卡的「人设」字段，要重来就等它自然修订。
2. **空态必须说明"什么时候会自动有"**，不要只写「暂无数据」——用户不知道后台什么时候跑。

## 4. 验收

- [ ] 只有一张角色卡时不出现 chips 行。
- [ ] 没定义时显示空态文案（不是空白，也不是「暂无」）。
- [ ] 版本历史按版本倒序，带 reason（bootstrap / revise）与时间。
- [ ] 实体列表点开能看到 `[主诉] …` 这种带类型的要点。
- [ ] 规范那一行点击返回设置页，不在这里就地编辑。
